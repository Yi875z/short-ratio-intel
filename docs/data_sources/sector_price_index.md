# 東証33業種別株価指数の取得元（フェーズ2-1）

- 調査日: 2026-08-11
- 実装: `src/macro_context/sector_price.py`
- 目的: 業種別空売り比率と株価反応を突き合わせて4象限で読むための騰落率を供給する

## 結論

**nikkei225jp.com が業種別株価ページ用に配信している履歴JSを使う。**

```
https://nikkei225jp.com/_data/_nfsDATA/min/country_jp_gyo_past.js
```

`Referer: https://nikkei225jp.com/chart/gyoushu.php` と通常のブラウザ UA を付けて GET する。
認証・APIキーは不要。既存の `market_quotes.py` と同一サイトで、実績のある取得元。

## 形式（実物確認済み）

```js
var GY=[];q=0;
GY[q]="2026/08/10,15:30,739.52,1066.13,2552.02, ... （33業種の指数値）";q++;
GY[q]="2026/08/07,15:30,739.13,1034.36,2581.73, ... ";q++;
```

- 1行 = 1営業日。`日付,時刻,33業種の指数値`
- 日付は `YYYY/MM/DD`、時刻は大引けの `15:30`
- 2026-08-11 時点で **44営業日ぶん（2026/06/09〜2026/08/10）** を保持
- 末尾に **1年前の参照行が1件**（例: `2025/08/08`）混ざる。ページの「1年」列用。
  前日として使わないよう、間隔が7暦日を超える場合は騰落率を算出しない実装にしている

## 業種の並び順（最重要・検証済み）

**値には業種名が付かず、並び順だけが業種の同定手段。** そのため推測せず実物で照合した。

`https://nikkei225jp.com/chart/gyoushu.php` のテーブルヘッダから業種名33個を抽出し、
`config/sectors.py` の `SECTORS_S33`（東証33業種の標準順、`9999 その他` を除く）と
1対1で突合した結果、**完全一致**を確認した。

| # | S33 | 業種 | ページ表記 | 2026-08-10 の値 |
|---|---|---|---|---|
| 1 | 0050 | 水産・農林業 | 水産農林 | 739.52 |
| 2 | 1050 | 鉱業 | 鉱業 | 1066.13 |
| 23 | 5150 | 空運業 | 空運業 | 249.61 |
| 33 | 9050 | サービス業 | サービス | 4354.65 |

空運業が全業種で最も低い水準（249.61）という特徴も、東証業種別指数の実態と整合する。

**値の個数が33でない応答は使わない**実装にしている。並び順に依存する以上、
本数が変わった時点で対応関係が壊れるため、黙って捨てるのが安全側。

## 採用しなかった候補

- **stock-marketdata.com**: 空売り比率（`karauri.html`）は取得しているが、
  サイト内リンクを全列挙しても**業種別株価指数のページが存在しない**。
- **nikkei225jp.com の `country_jp_gyo.js`（最新日のみ）**: 当日値と前日比を持つが
  履歴が無い。過去日のレポート再生成ができないため、履歴版 `_past.js` を採用した。
- **TOPIX-17 業種別ETF（1617.T〜1633.T）**: Yahoo Finance で取得できるが
  17業種であり33業種と対応が取れない。情報が落ちるため見送り。

## 注意点

- 騰落率は**連続する2営業日の指数値から自前で計算**している。
  `country_jp_gyo.js` の `G2`（前日比）をそのまま使わないのは、履歴版に前日比の列が無く、
  両者で算出方法が食い違うのを避けるため。
- 取得失敗・形式変更・対象日が履歴外のいずれも**空を返す（fail-soft）**。
  プロンプトは株価列を「N/A」とし、比率のみで従来どおり組み立てられる。
- 履歴が約2ヶ月ぶんしかないため、それより古い日のレポートを再生成しても株価は付かない。
  これは仕様であり、無い数字を推測で埋めない。
